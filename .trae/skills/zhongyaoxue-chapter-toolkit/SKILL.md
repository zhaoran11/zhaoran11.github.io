# 中药学章节智慧工具（三件套）

把《中药学》教材每一章做成三个可直接课堂使用的单页 HTML 工具，形成"认知识 → 练选药 → 析真案"的能力进阶。第 1 章《解表药》为已验证的参考实现，后续章节沿用同一结构与配色，只替换数据。

## 三件套分工（不要混用）

| 层级 | 工具 | 学生任务 | 适用 |
|---|---|---|---|
| 知识层 | 知识图谱 | 看、点、连：证型→治法→药物→方剂→禁忌 | 课前预习、课中串讲 |
| 初级 | 辨证练习器 | 从提示症状中勾选→辨证→选治法→选药 | 大一初学，建立"症—证—药"对应 |
| 进阶 | 医案分析器 | 读完整病案→提炼四诊→析病机→定治法→排君臣佐使→判药对配伍 | 学完本章后，练真实案例 |

## 执行步骤

1. **确认口径**：章节名、教材版本、证型与药物名称（须与教材一致）、初级医案数（默认 6）、进阶病案数（默认 2–3）。
2. **建目录**：`/workspace/中药学智慧工具/<章名>/`，必须与 `lib/` 平级。
3. **复制三个模板**并改名：`知识图谱.html`、`辨证练习器.html`、`医案分析器.html`。保留 `../lib/echarts.min.js`。
4. **只替换数据区**，引擎代码一律不动。
5. **改标题与分类**：`<title>`、页头、图谱的 `CATS`/`COLHEAD`、练习器的药物表。
6. **跑自检**（见下）。
7. **更新总入口**：进度表改为 `done`，追加三张工具卡片。

## 数据结构

### ① 知识图谱

```
RAW   节点  { id: { n:显示名, c:分类号, x, y, s:大小, shape, step:环节1-5 } }
LINKS 连线  [ ["起点id", "终点id"] ]
INFO  详情  { id: { tags:[标签], rows:[ [标题, 内容, 是否标红] ] } }
分类号     0=证型 1=治法 2=药(第一组) 3=药(第二组) 4=方剂 5=禁忌
```

- 固定逻辑坐标，禁用自动布局，避免课堂投影抖动。
- 五列主线：证（理）→ 治法（法）→ 药物（药）→ 方剂（方）→ 禁忌（用）。
- 节点 25–40 个；每味药只挂一条治法；禁忌不悬空。

### ② 初级练习器

```
SYM      症状  [ { id, n } ]
PATTERNS 证型  { id, name, branch, must:{症状id:权重}, like:{...}, against:{...}, core:[药物id], formula }
HERBS    药物  { id: { n, t:性味, b:"han"|"re", core:[证型id], bad:{证型id:原因}, warn } }
CASES    医案  { complaint, body, tongue, present:[], extra:[], pattern, methods:[], correctMethod, analysis }
```

评分：四诊 20 + 辨证 30 + 立法 20 + 选药 30；四诊少于 3 项时辨证不计分。

### ③ 进阶医案分析

```
text     病案原文（可用 <em></em> 标关键句）
sxOpts   四诊选项 [{id,n,ok}]         ok=false 为干扰项，建议 4–6 条
bj       病机选项 [{n,ok,why}]        why 是误判时的解释，建议 3 正确 + 3 干扰
zf       治法选项 [{n,ok}]            单选，1 正确 + 3 干扰
pool     可选药物 id 数组             10–14 味，含 4 味以上禁忌药
need     必选药 {id:{w:权重, role}}   role ∈ jun/chen/zuo/shi
ok       可用非首选 {id:{w}}
bad      性味相悖 {id:{why}}
pair     单药对 {opts:[[a,b]], ans:"a|b", rel:"相须", relOpts:[...], meaning:"..."}
pairs    多药对（推荐）[{opts,ans,rel,relOpts,meaning}, ...]，引擎自动兼容 pair
analysis 参考答案 {bj, zf, roles:[[药,角色,作用]], diff, orig:"原案辨证与用方",
          herb:{n,t,g,rows:[[功效,本案对应,配伍]]}}   // herb 可选
```

评分：四诊 15 + 病机 20 + 治法 15 + 选药 25 + 君臣 10 + 配伍 15 = 100；配伍分在多个药对间均分。

**进阶题设计原则**
- 病案必须完整（主诉、现病史、舌脉、病程），且**只给四诊资料**，不要写入原案辨证结论与处方——否则学生直接抄答案；原案结论放进 `analysis.orig`，提交后才展开。
- 必须设置"似是而非"的干扰：同类异证、错误治法、相悖药物。
- 讲"某章第一味药"时，用 `analysis.herb` 把该药的性味归经、功效、**每项功效对应的本案表现与配伍**列成表，落到"为方剂学服务"。
- 一个案例可设 2 组药对，用不同配伍关系（如相须 vs 相使）形成对照，比单药对更能讲透配伍。
- `meaning` 要写"为何相配、配后增强了什么"，不能只罗列两药功效。
- `diff` 必须写与最易混淆证型的鉴别点。

## 自检（交付前必跑）

```bash
# 1) 语法：提取内联脚本做 node --check
# 2) 引用完整性：pool/need/ok/bad/pair 中的药物 id 必须在 HERB 中存在；
#                ans 必须出现在 pair.opts；rel 必须在 relOpts 内；need 必须在 pool 内
# 3) 评分：构造"全对"应得 100，"全错"应得 0，"只选君药"应落在 70–88
# 4) 布局：1920/1600/1440/1366/1280/1024 六种宽度无重叠、标签不越界
```

任何一项不过，先修数据，不要改引擎。

## 常见坑

- 章节文件夹放错层级 → echarts 404，页面空白。
- `CATS` 忘了改 → 仍显示"解表药·风寒"旧分类名。
- 进阶案把病案写成症状罗列 → 丧失"读案"训练价值。
- `need` 的角色与实际方义不符（如把佐药标成君）→ 君臣佐使得分失真。
- 干扰项太少或太离谱 → 学生靠排除法即可得分，失去区分度。
- 医案 `analysis` 写成教科书泛论 → 应写"本案为何选它、为何不选它"。
