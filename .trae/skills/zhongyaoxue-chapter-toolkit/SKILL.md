# 中药学章节智慧工具（知识图谱 + 辨证用药练习器）

把《中药学》教材每一章，做成两个可直接课堂使用的单页 HTML 工具。第 1 章《解表药》为已验证的参考实现，后续章节沿用同一套结构，只替换数据。

## 资产位置

| 用途 | 路径 |
|---|---|
| 总入口（含 21 章进度表、调用说明） | `/workspace/中药学智慧工具/index.html` |
| 图表库（共用） | `/workspace/中药学智慧工具/lib/echarts.min.js` |
| 知识图谱模板 | `/workspace/中药学智慧工具/_模板/知识图谱模板.html` |
| 练习器模板 | `/workspace/中药学智慧工具/_模板/辨证练习器模板.html` |
| 参考实现（解表药） | `/workspace/中药学智慧工具/解表药/` |

**不要改动模板与解表药的既有文件**，只新建章节目录。

## 执行步骤

1. **确认口径**：向用户确认章节名、教材版本（规划教材/自编教材）、证型与药物名称是否按教材原文、练习器需要几个医案（默认 6 个）。
2. **建目录**：`/workspace/中药学智慧工具/<章名>/`，必须与 `lib/` 平级，否则 `../lib/echarts.min.js` 失效。
3. **复制模板**：`知识图谱模板.html` → `知识图谱.html`；`辨证练习器模板.html` → `辨证练习器.html`。保留 `../lib/echarts.min.js` 引用不动。
4. **只替换数据区**（见下节），其余代码一律不动。
5. **改标题**：`<title>`、页头章节名、图谱的 `CATS` 分类名与 `COLHEAD` 列标题。
6. **跑自检**（见下节），全部通过再交付。
7. **更新进度**：把 `/workspace/中药学智慧工具/index.html` 中对应章节改为 `done`，并追加该章的工具卡片链接。

## 数据结构规范

### 知识图谱

```
RAW   节点  { id: { n:显示名, c:分类号, x, y, s:大小, shape, step:环节1-5 } }
LINKS 连线  [ ["起点id", "终点id"] ]
INFO  详情  { id: { tags:[标签], rows:[ [标题, 内容, 是否标红] ] } }
分类号     0=证型 1=治法 2=药(第一组) 3=药(第二组) 4=方剂 5=禁忌
```

- 布局：固定逻辑坐标（x 分列、y 分层），不要用自动布局，保证课堂投影不抖动。
- 主线固定五列：**证（理）→ 治法（法）→ 药物（药）→ 方剂（方）→ 禁忌（用）**。
- 每味药必须挂到唯一一条治法上；方剂连线到其组成核心药；禁忌只挂在具体药物/方剂上，不悬空。
- 节点总数建议 25–40，单章一屏可读；超过 40 应拆分或只保留大纲药。

### 辨证用药练习器

```
SYM      症状  [ { id, n } ]
PATTERNS 证型  { id, name, branch, must:{症状id:权重}, like:{...}, against:{...},
                core:[药物id], formula }
         branch: "han"(偏温) | "re"(偏凉)，用于判定选药性味相反
HERBS    药物  { id: { n, t:性味, b:"han"|"re", core:[证型id],
                      bad:{证型id:原因}, warn } }
CASES    医案  { complaint, body, tongue, present:[], extra:[],
                pattern, methods:[], correctMethod, analysis }
```

- `must` 为必要条件（权重高），`like` 为或然条件，`against` 为矛盾症状（负分）。
- 6 个医案应覆盖该章的主要代表方，并至少设 1 个**易错对照案**（如解表药中的"有汗/无汗"）。
- `bad` 用于制造教学冲突点：学生选到性味相反或禁忌药时给出具体理由。
- 评分构成固定：四诊 20 + 辨证 30 + 立法 20 + 选药 30；四诊少于 3 项时辨证不计分。

## 自检（交付前必跑）

```bash
# 1) 语法
python3 -c "
import re;h=open('<路径>/知识图谱.html',encoding='utf-8').read()
open('/tmp/a.js','w').write('\n'.join(re.findall(r'<script>(.*?)</script>',h,re.S)))"
node --check /tmp/a.js

# 2) 引用完整性：节点 id 与 INFO 一一对应、LINKS 两端都存在、无孤立节点
# 3) 辨证：每个医案在 present+extra 输入下，正确答案必须排第一，且与第二名分差≥10
# 4) 布局：在 1920/1600/1440/1366/1280/1024 六种宽度下无节点重叠、标签不越界
```

任何一项不过，先修数据，不要改引擎。

## 常见坑

- 章节文件夹放错层级 → echarts 404，页面空白。
- `CATS` 忘了改 → 新章节仍显示"解表药·风寒"等旧分类名。
- 证型 `core` 里漏写药物 id → 选药环节无"首选"判定。
- 药物 `b` 字段与证型 `branch` 不一致 → 反向提示误报。
- 医案 `analysis` 写成教科书式泛论 → 应写"本案为什么选它、为什么不选它"。

## 交付话术

告知用户：文件路径、节点/医案数量、自检结果、课堂 6 次点击的演示动线，以及本章可继续扩展的点。不要再重复解释工具原理。
